## [Unreleased]

### Added
- Repository skeleton: package layout (`qprogram`, `spacetime`, `tableau`, `topological`, `gui`), packaging, tests.
- `zxqec.qprogram.QProgram`: programs as sequences of circuit stages and permutations on a hardware layout; master space-time graph with `stage` / `logical_qubit` vertex data on top of `pyzx.spacetime`; stage and block sub-diagrams; measured qubits reborn by `Reset`; per-stage renaming of PyZX's generated symbolic variables.
- `zxqec.qprogram.LevelManager` / `Block`: level-up of consecutive stages and merging of blocks separated by stages on disjoint qubits (port of the thesis `GateLevelManager`).
- `zxqec.spacetime.Topology` (port of the thesis class, with `grid` / `line` constructors) and `induced_subdiagram`, which cuts any set of spiders out of a program graph as a valid ZX-diagram, keeping idle wires and attributing every edge to its later endpoint.
- `zxqec.gpf`: reduction to generalized parity form with phases. `to_gpf` (thesis Algorithm 2) keeps Pauli/Boolean phases on the spiders and uses PyZX's Boolean bialgebra rule; non-Pauli phases become stem+leaf gadgets; Hadamard edges are removed by recolouring and recorded on boundary wires. `reduce_gpf` (Algorithm 3) does the split-matrix row reduction of both layers over GF(2) with the phases carried along -- only free rows are ever sources -- and returns the detectors (Boolean parities of measurement outcomes that must vanish) and whether the diagram is zero. `isolate_paulis=True` gives the thesis's phase-free skeleton.
- Fixed: `measurement_report` reported a Boolean phase sitting on a *gadget hub* as part of the Pauli frame. Such a phase negates the gadget's phase instead (a `pi/4` leaf acts as `-pi/4`, i.e. `T` becomes `T-dagger`), so following `frame_values` gave the wrong correction -- on the Steane T injection it claimed a `Z` where a conditional `S` is needed. The report now separates the two: `frame` and `frame_values` carry only Pauli corrections, and `gadget_signs` / `gadget_sign_values` carry the conditional rotations. (Reported by an external review of the code.)
- `to_gpf` removes identity spiders and fuses same-colour neighbours before pushing Hadamards to the boundary. Two consequences: a diagram whose only odd-Hadamard cycle runs through an identity is now accepted rather than rejected, and two gadgets sharing a parity are fused, which recovers a detector the reduction used to miss (`pi/4` and `3pi/4` leaves hiding a `pi` phase).
- `push_hadamards_to_boundary` now chooses each component's colouring so that boundary Hadamards land on inputs where possible, so a reduced diagram reads "Hadamard first, then the outcome-dependent Paulis" -- the order in which a decoder applies corrections. `frame` is reported from input to output, and `frame_values` documents that it is read in the input frame.
- `to_gpf` checks its post-conditions before returning, and `is_gpf` now also checks (G3)/(G4) -- non-Pauli phases only on gadget leaves. `reduce_gpf` raises instead of stopping silently when the Z/X alternation does not settle within `max_rounds`, and `phase_mod2` rejects a non-Pauli constant rather than truncating it.
- `tests/test_gpf_random.py` checks the detectors themselves: every violated constraint must give a zero branch and every allowed branch must be non-zero (completeness asserted for Pauli-only diagrams).
- Fixed: the zero verdict of `reduce_gpf` looked for the constant 1 among the constraints, which misses an inconsistent system such as `{c, c + 1}` where every branch vanishes. It now solves the constraints over GF(2); the new `zxqec.gpf.constraint_system`, `unsatisfiable` and `detector_rank` expose that system, the verdict and the number of independent detectors.
- Fixed: an isolated Z--X pair was dropped as a unit scalar regardless of its phases, but `<X(3pi/2)|Z(pi/2)>` is exactly zero. Such a pair is now dropped only when at least one phase is Pauli. (Reported by an external review of the draft; PyZX's own scalar bookkeeping already caught the case that reaches it through `to_gpf`.)
- Fixed: `equal_for_all_assignments` reported a false mismatch whenever a branch of the protocol is the zero map, because `pyzx.compare_tensors` normalises by the scalar. The new `zxqec.gpf.same_map` compares two diagrams with the scalar kept and treats two zero maps as equal; the verification helper uses it.
- Fixed: a spider with a non-Pauli phase sitting directly on a boundary wire was treated as a gadget leaf, after which the boundary padding put two same-coloured spiders in a row and the result was not in GPF shape (the map was still correct). Found by random differential testing against the thesis implementation; `tests/test_gpf_random.py` now checks `to_gpf` and `reduce_gpf` on random diagrams with Pauli, Boolean and non-Pauli phases.
- `zxqec.gpf.measurement_report` and `QProgram.measurement_report(level, index, context=True)`: the detectors and the Pauli frame turned into a per-measurement table -- each outcome is part of the frame (the map depends on it), fixed by a detector, tied to other outcomes, or gauge -- plus the dimensions of the outcome space (`forced + steering + gauge`), `violated(outcomes)` and `frame_values(outcomes)` for checking a run, and `internal_detectors()` for the ones a block can check on its own. A block's measurements are classified in the context of the whole program by default (`context=False` analyses the block alone, where nothing is deterministic).
- `QProgram.add_circuit(..., physical=True)` for stages written in the physical frame (qubit indices are wire positions, relabelled through the current mapping) and `QProgram.quantum_graph()` (master graph without the classical-bit wires); `stage_graph` / `block_graph` take `classical=False` for the same on a sub-diagram.
- `examples/SteaneTInjection.ipynb`: the second case study, a `T` gate injected into the Steane code. A derived-and-checked encoder with its transversal gates (`H^7` is logical H, `S^7` is logical S-dagger, seven CNOTs are a logical CNOT), the physical protocol as a 20-qubit program, level-up into logical operations with the measurement report per block, and the logical operator it implements per branch. The conditional-`S` correction is a conditional Clifford, which the symbolic framework cannot carry, so the branches are checked separately -- the smallest realistic motivation for feedforward support.
- `examples/FoldTransversalHadamard.ipynb` and `examples/circuits/ft_h/`: thesis case study 1 verified with symbolic measurement outcomes -- the protocol reduces to `H` with an outcome-dependent Pauli frame and 24 detectors, and to exactly `H` at all-zero outcomes (the analysis exposed a mis-wired check in the thesis's `ft_h_5.qasm`, invisible under post-selection; corrected); `sample_consistent_assignment` solves the detectors to draw allowed outcomes. `examples/interactive_fold_h_3d.py` opens the protocol's 2+1D view in a window (whole protocol, one stage or one block). `examples/TrackingOutcomeVariables.ipynb` + `track_variable.py` trace an outcome variable through every rewrite of `full_reduce` and `reduce_gpf`, showing that absent variables live in the scalar (the detectors).
- `zxqec.spacetime.web`: interactive notebook views built on PyZX's JavaScript viewers -- `draw_web` / `draw_program_web` (d3: draggable spiders, zoom, time on the horizontal axis, delays as squiggly wires with `Δ` labels that follow dragging, vertical edges in crowded columns bent as in `draw_matplotlib` so a CNOT across a qubit is unambiguous, timestep shown above each spider, blocks of a level shaded behind the diagram). The example notebooks use this for the 2D views; the matplotlib views remain for scripts and static figures and gained a `classical` option (classical-bit wires are no longer drawn by default).
- `zxqec.spacetime.drawing`: `draw_program` (PyZX's 2D drawing with time as the horizontal axis and the blocks of a level shaded) and `draw_program_3d` / `draw_graph_3d` (the 2+1D view of the thesis `draw_topology_3d`: spiders at their topology position and timestep, hardware graph on the first/last layer, blocks as slabs; without the button widgets), with named viewpoints (`view='top'` bird's-eye, `'front'`, `'side'`) and `draw_program_views` for several viewpoints side by side; `buttons=True` adds view buttons to the figure for use in a window. Programs with more than 15 occupied timesteps get a thinned time axis instead of one tick label per timestep.
