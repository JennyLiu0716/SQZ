## [Unreleased]

### Added
- `draw_graph(..., label_side='clear')`: every phase label and every name (`names=`) placed where it covers no edge, no spider and no other label, as drawn. A label first tries its own side (right of the spider for a phase, left for a name), moving out up to two label widths, so labels in a column of gadgets closer than a label is tall alternate between two places on their own rows, and a name on an input wire goes past the wire's end; then the other sides, nearest first; if no place is free, the one that covers least. Labels are placed from the top down. Opt-in: the other values of `label_side` are unchanged, so no existing picture changes. The SQZ paper's Section 5.2/5.3 figures use it (`paper/sqz_triorth/make_figs_52.py`); a check that no label there touches anything is `paper/sqz_triorth_tools/check_label_overlaps.py`. Test in `tests/test_drawing.py`.
- `examples/DecompilationFlow.ipynb`: the decompilation flow chart box by box, and the flow route tested against the matrix route on every block of four programs. `LogicalAction.with_route(route)` (a copy that names its classes the other way) and `CliffordPlusPhases.to_graph()` (the Clifford part with its phase effects plugged back) for it.
- `LogicalAction.tableau()` and `zxqec.codes.clifford_tableau(g)`: a Clifford logical gate as its tableau, where it sends each logical X and Z, with signs that are Boolean polynomials in the outcomes (the Pauli frame of every run at once), read off the Choi state by Gaussian elimination: no matrix, polynomial in the number of logical qubits. `CliffordTableau.name()` names it from the tableau: the gate up to a Pauli (looked up per connected part of one or two logical qubits among the named Clifford gates, so also beyond three logical qubits) and the Pauli correction as a formula in the outcomes. Raises `NotCliffordError` for a non-Clifford gate; `branches()` / `verdict()` (the matrix route) are unchanged and remain the default. On the Clifford case studies (Shor, fold-transversal H, code switching, CNOT by teleportation) it gives the same name as the matrix route.
- `LogicalAction.clifford_part()` and `zxqec.codes.clifford_plus_phases(g)`: a diagram as a Clifford isometry `U` followed by phase effects on extra outputs (`to_gpf`, then `open_leaves` on the non-Clifford leaves), with `U`'s tableau and isometry AP normal form.
- `iap_normal_form(e, generators='lightest')`: `generators='echelon'` reads the Choi state without listing the stabilizer group; the normal form is the same (a sign that depends on outcomes may be written differently, e.g. `c[2] + 2` for `c[2]`). The default is unchanged.
- `draw_graph(..., names=None)`: an opt-in map from vertices to names, each written just left of its spider at `label_size` (12 points when it is None), also with `time_axis=True` (e.g. the bits of a Z-layer after `change_variables`). Without it the drawing is unchanged.
- `zxqec.gpf.normalize_gadget_angles(g)`: every Z-gadget's angle brought into `(-pi/2, pi/2]`, in place: an angle `a` in `(pi/2, 3pi/2]` becomes `a - pi`, and the `pi` goes onto each spider the hub reads (so `5pi/4` is drawn as `pi/4` and a `pi` on those spiders). The sign that depends on the hub's outcomes is dropped, so the map is kept up to a non-zero scalar in every run; meant for drawing, on a copy. Only gadgets of GPF shape are changed (one Z-leaf on the hub, plain edges). Opt-in; nothing calls it.
- `zxqec.gpf.open_leaves(g, leaves=None)`: a clone with the given gadget leaves taken off and a new output on each hub (after the old outputs), and the new outputs. Plugging each leaf back as an effect gives `g`; with every leaf off and the other phases Pauli the clone is Clifford, so `code_of` reads it. A `Z` on the new output of a Z-leaf is a `pi` on that leaf (an `X` for an X-leaf). Opt-in; nothing calls it.
- `zxqec.spacetime.save_panels(fig, pattern, pad=0.04, dpi=200, formats=('pdf',), titles=False)`: each panel of a figure (e.g. each block of `draw_blocks_3d`) saved as a file of its own, cropped to what that panel draws (found from its ink, so 3D labels outside the axes' box are kept), to place the panels one by one in a document; the figure is left as it was. It reproduces the PLanQC abstract's Fig. 4(c) panels exactly (the crop that `paper/planqc2027/v30-fig5/make_fig5c_panels.py` did by hand), and the SQZ paper's fold-transversal Hadamard figure now uses it.
- `zxqec.spacetime.block_spans(program, level, time_axis=True, even_rows=False, classical=False)`: where `draw_program` shades each block of a level, as intervals in the drawing's coordinates (a test checks they are the shading). With the drawing's axes filling the figure, they give where each block starts and ends as a fraction of the width, so a paper's figure can draw lines from the blocks to other pictures without measuring the drawing by hand. The SQZ paper's fold-transversal Hadamard figure uses it for the links from panel (b) to panel (c).
- `QProgram.measured_operators(stage)`: what each measurement of a stage measures, as a Pauli operator (with its sign) on the qubits entering the stage: the measured Z carried back through the stage's Clifford gates with Stim, a reset or a fresh initial state taking away the Z (or X) it fixes; `None` for a result with no fixed operator. On the fold-transversal Hadamard each result of a round of checks comes out as its check (c[9] is X on qubits 1 and 4, ...). `draw_measurement(..., results=...)` puts each result on the check it measures, so a round shows what it reads even where the result is always 0 (the X checks of code 2, c[9] to c[12]).
- `StabilizerCode.measurement(kind)` and `draw_measurement(coords, kind, ...)`: the ideal measurement of all checks of one kind, with their signs: the projector onto the states where each X (or Z) check has its sign, as a ZX-diagram (an X-spider on each qubit joined to a Z-spider per check with its sign as its phase; the other colours for Z checks), and the same drawn on the layout as a round of checks is drawn by hand: each qubit with its input stub above and output stub below, a spider on each face, no logical wire. Checked against the projector built from the Pauli matrices. `draw_encoder`'s placement and drawing moved into a shared helper, its pictures byte-identical. Used for the rounds of checks between the first encoder and the last decoder of the fold-transversal Hadamard in the PLanQC abstract.
- `QProgram.code_at(stage, outcomes='latest')`: each stabilizer sign written in the result of the last round that measured the check by `stage`, instead of the first (the default, as before). The detectors of the cut say that the rounds read the same value, so both are the same code in every run without faults. On the fold-transversal Hadamard the signs after the round in code 2 are c[5] to c[8] and after the round in code 1 c[13] to c[16], instead of c[1] to c[4] everywhere. Built on `reduce_modulo(..., latest=True)` / `phases_modulo(..., latest=True)` (the earliest outcomes taken as pivots, so a phase is written in the latest ones) and the new `StabilizerCode.signs_modulo(constraints, latest=False)`.
- `StabilizerCode.draw_encoder(coords, adjoint=False, checks='auto', ...)`: the ideal encoder (or, with `adjoint`, the decoder) drawn on the hardware layout, as encoders of surface codes are drawn by hand: each qubit's spider at its place with a short stub for its wire, each check's spider in the middle of its face (outside the edge for a check on two qubits), the logical spider beyond its logical operator, and the faces of `layout_checks` behind, in `face_colors`. The encoder is built on those faces (each face's sign the sum of the signs of the stored generators whose product it is), so every check spider sits on its own face even when the code stores other generators (a distance-5 surface code read by `code_of`). The stabilizer signs, Boolean functions of the outcomes, are the check spiders' phases; `checks='auto'` picks the colours in which each sign sits on its own check (green checks for signs on X checks, red for signs on Z checks). `wire_ends='tick'` draws the wire ends bare instead of as dots. Spiders are kept apart: a logical spider goes to the nearest place beyond its operator that is clear of the qubits, of the other logical spiders and of the stubs' lines, and a check spider whose middle is taken (a symmetric or one-dimensional layout) moves to the nearest free place; the label of a check on the edge goes outside it. Known limits: long signs (sums of outcomes) beside a qubit's spider can run over the next qubit, and two checks on facing edges of two patches put their half-discs close. PyZX draws the diagram; without `figsize` every picture is 0.3 inch per unit, so pictures drawn with the same `spacing` share one scale. Used for the pictures under the gadget boxes of the fold-transversal Hadamard in the PLanQC abstract, in place of hand-drawn ones that showed every sign as 0.
- `StabilizerCode.encoder(checks='Z')`: the same encoder in the other colours (a Z-spider on each qubit, an X-spider for each Z stabilizer with its sign as its phase, the logical inputs wired along the logical Z operators). The default, `checks='X'`, is the diagram as before, vertex for vertex. `encoder(stabilizers=...)` builds it on other generators of the same group, with their signs. Checked equal to the default for every value of the signs on the fold-transversal Hadamard's codes, on random CSS codes and on codes with several logical qubits.
- `draw_stage_layout(program, stage, wires=None, code=None, ...)` (`zxqec.spacetime`): one stage drawn flat on the program's topology, each spider at its wire's place, as a transversal layer or a permutation is drawn by hand. A wire with only a Hadamard is a stub through a Hadamard box; a wire that a permutation moves runs from its old place to its new one, bowed outwards where a straight line would pass through another place (the quarter turn of the fold-transversal Hadamard draws as a square and a diamond). Each moved wire has a stub above its old place and below its new one; two wires that trade places bow apart. Meant for stages one timestep deep (a two-qubit gate between places one above the other draws its wire on their stubs). `code` draws its faces behind.
- `StabilizerCode.same_logicals_as(other, by='label' | 'position')`: whether two codes name the same logical operators, each logical X and Z of one being that of the other up to stabilizers (signs ignored); `None` when they are not the same code (`same_code_as`, qubits matched the same way). Matching by position can map one logical qubit onto another (a test moves two qubits of the [[4,2,2]] code and swaps its X1 and X2). `summary` uses it: a block with the role *logical gate* or *transversal gate* that ends in the code it started in (by label, or else by position) gets the check "ends in the code it started in, with the same logical X and Z (qubits matched by label | by their place on the chip)", so that its logical action is a gate on that one code; when the logical operators differ, the check fails and says that the action is named after the code after the block. On the fold-transversal Hadamard, the block made of the Hadamards, a round and the quarter turn passes by position. A block that changes the code gets no such line. Before, this needed a hand check: the logical action is named after the logical operators of the code after the block, read qubit by qubit.
- `group_stages(groups, one_level=True)` makes one new level, level 1, with all the groups (`LevelManager.group`); by default each group is still a `level_up` of its own, so the levels in between hold some of the groups, as before. With named roles on every block of a protocol, the default left five levels nobody asked for under the fold-transversal Hadamard's six blocks, and the levels window's slider went through them. Ranges are now all checked before any level is made.
- `view_levels_3d(..., controls=False)`: the 3D levels window as a still figure, as `view_levels` already allows: no slider, block buttons or view buttons, the pictures and the text moved into their place, and no "drag to turn it" in the title; the methods (`set_level`, `set_block`, `set_view`, ...) still move it. The default keeps the window as it was. Used for the level figures of the fold-transversal Hadamard (`paper/sqz_fold_h_levels`).
- Simplification during level-up (L. Yeh's suggestion). A block can name a rewrite when it is made: `level_up(..., rewrite='gpf')`, the same for `merge_blocks`, and an optional fifth entry in the groups of `group_stages`; `None` (the default) only groups, as before. `QProgram.reduced_block(level, index)` builds the block's diagram from its children: each child's diagram, rewritten if the child has a rewrite of its own, glued in order along the qubit wires (`QProgram._glue`, which builds the master graph), then the block's own rewrite. It returns a `ReducedBlock`: the diagram, its children, the detectors the rewrites removed (by this block and below), spider counts before and after, and the time; results are cached per block and dropped when a stage is added. `describe_reduced(level)` lists them, and `describe_level` shows each block's rewrite. `QProgram.reduced_level(level)` glues all the blocks of a level the same way: the whole program with every block of that level replaced by its rewritten diagram (a `ReducedLevel`: the diagram, the blocks, which vertices come from which block, the detectors removed); levelling up only stages 2 and 3 of the fold-transversal Hadamard with `'gpf'` gives the circuit with that round as its normal form, 267 spiders instead of 311. Rewrites by name (`zxqec.qprogram.REWRITES`): `'gpf'` and `'gpf-no-gadgets'` (`reduce_gpf`, keeping the detectors it removes; earlier markings of gadget leaves are cleared first, since a rewritten child glued to its neighbours need not keep them), and PyZX's `'full_reduce'`, `'clifford_simp'`, `'spider_simp'`, `'teleport_reduce'`; `register_rewrite(name, function)` adds more. The rewritten diagrams are a view: `code_at`, `logical_action` and `summary` still use the cut diagrams. Checked: with no rewrite anywhere, the glued children equal the cut diagram at every level, and every rewrite equals it on the runs its removed detectors allow (a three-qubit program with a measurement, a reset, a fed-forward correction, a T gate and a permutation, run by run); the fold-transversal Hadamard reduced block by block and then as a whole gives 2 spiders and 24 detectors, and d = 3 cultivation 13 spiders and the same 28 independent detectors, as reducing each program at once. `zxqec.spacetime.view_levels(program)` opens a window for walking through the levels: the program with the blocks of a level shaded, the selected block outlined and the blocks it was made from dashed; in the middle the program as that level rewrites it (`reduced_level`), each block's part shaded in its colour and the selected block outlined (the pictures are the library's own drawings, `draw_program` and `pyzx.draw_matplotlib`, rendered to images), the block's diagram after its rewrite (with the outcomes in its phases written modulo the detectors removed on the way, `phases_modulo`, as the examples draw normal forms: level by level, the fold-transversal Hadamard's frame comes out as `c[15] + c[16] + c[13] + c[14] + c[5] + c[7] + c[8] + c[0] + c[1] + c[3] + c[4]`, which is `c[0] + c[1] + c[2] + c[3] + c[4]` plus detector parities, and is drawn as the latter, as reducing at once gives) or cut out of the circuit, what the block is and where it came from, a level slider, block buttons and the arrow keys; moving between levels keeps the focus on the same stages. Spiders can be dragged in the 2D pictures, so labels that overlap can be pulled apart: a drag moves the spider in a copy of the graph (`clone`, which keeps vertex numbers; the program's own graph never moves) and the picture is drawn again by the same function, so it stays PyZX's drawing; moves in the program picture hold on every level, moves in a block picture belong to that block. *spread out block* lays a crowded block out with PyZX's force-directed layout (`pyzx.drawing.auto_layout_vertex_locs`, with a fixed seed), and *reset positions* undoes all moves. For this, `draw_program` takes `positions={vertex: (row, qubit)}`, and `program_layout(program)` returns the graph with the time-axis layout it draws. `zxqec.spacetime.view_levels_3d(program)` is the same window with the program in 3D, as `draw_program_3d` draws it (the hardware layout flat, time upwards): the blocks of the level as slabs, the selected block outlined in bold and the blocks it was made from dashed; the program is drawn once and only the slabs change between blocks and levels, so a viewpoint turned with the mouse is kept; buttons for the named viewpoints (`set_view`). In the middle the program as the level rewrites it, in 3D too and turning with the program (`zxqec.spacetime.draw_level_3d(program, level)`, laid out by `level_layout_3d`): what has a place in space-time is drawn there, a block without a rewrite where it is in the circuit (at level 0 every spider is exactly where `draw_program_3d` draws it, tested); a rewritten diagram has none, so inside a rewritten block only the ends of its wires are fixed (where each wire enters or leaves the block) and every spider sits over the wire ends nearest to it in the diagram, at a height dividing the block in the ratio of its distances to the inputs and the outputs (in a normal form, the Z-spiders low over their input wires, the X-spiders high over their output wires); the layout is described as a layout, not as where or when anything happens. On the right a rewritten block stays PyZX's 2D drawing with spiders to drag (a rewritten diagram has no place in space-time), and a block cut out of the program (*plain diagram*, or a block without a rewrite) is drawn in 3D too. `examples/interactive_levels.py --3d` opens it. For this, `draw_graph_3d` takes `finish=False` (leave the figure open, for drawing into a window) and `positions` (`(x, y, t)` for some vertices); its defaults and its pictures are unchanged. `examples/interactive_levels.py` opens it on the fold-transversal Hadamard or d = 3 cultivation, and `examples/LevelUpWithRewrites.ipynb` walks through all of this. Tests in `tests/test_rewrites.py`. No existing output changes.
- `zxqec.gpf.decompose_terms`: a reduced diagram as a sum of terms, one for each value of its hidden spiders (L. Yeh's decomposition): every Z-spider that is not on an input is split into |0...0> + |1...1>, every X-spider that is not on an output into |+...+> + |-...->, and with `split_gadgets=True` the gadget hubs too. The diagram is first cut into its connected parts, whose terms multiply, so each part is split on its own; a part with more than `max_terms` terms (1024) is reported but not split. Each term is reduced again and cut into pieces: a single-qubit piece is named from a short list (Paulis, H, S, T, T X T^dag, ..., and single-qubit states and effects) together with what it does to an X, Y or Z error on that qubit; a larger piece is reported as linking its qubits. Two labellings of the hidden bits: `'as reduced'` keeps the labels of `reduce_gpf`; `'fewest links'` replaces a hidden bit by itself plus some inputs, so that each input's Z-spider reaches as few outputs as possible. On the d = 3 cultivation double-check, `'as reduced'` gives two terms that link all seven code qubits; `'fewest links'` (hidden bit + input 14) gives "nothing" and T X T^dag on every code qubit, which turns X errors into Y errors, and with S for T "nothing" and Y on every code qubit, which keeps every error. The check reported for distance, agreed with L. Yeh: in every part, every term maps each Pauli error to the same Pauli, up to a sign (`Decomposition.same_error_action`). It reads every piece that is a unitary up to a scalar, linking qubits or not, through the Pauli string on its outputs that an X, Y or Z error on each input becomes (`Piece.paulis`, `Term.pauli_action`); pieces with no output (an input that ends in an effect, such as a measured qubit) or no input (a state) are left out. False if two terms send some error to different Paulis or a term sends one to something that is not a Pauli; None if neither and some piece cannot be read (not a unitary, or not contracted). Products of single-qubit Clifford gates are not enough: on the d = 3 double-check with real T, `'fewest links'` gives "nothing" and T X T^dag, single-qubit Cliffords, and the check fails (X kept by one term, turned into Y by the other), as the fault distance (2, Chan et al.) says; with S it passes (3); with `'as reduced'` the terms are projections and the check has no answer. Both d = 5 double-checks fail it with `'fewest links'` (the d = 5 one in all 16 runs its detectors allow, the d = 3 one in 64 sampled runs of its 2^19). Whether the terms are single-qubit is information, and only expected of non-Clifford parts, since a Clifford part generally has terms that link qubits, as one CNOT does: `Part.clifford`, `Decomposition.non_clifford_single_qubit` (and `.single_qubit` for all parts); the table marks each part Clifford or non-Clifford. The exact term diagrams (before their reduction) add up to each part. Tried on every block of the fold-transversal Hadamard, the Steane T injection and d = 5 cultivation; the two d = 5 double-checks behave like the d = 3 one, and the d = 5 rounds of checks have a part with 18 hidden spiders, which is not split. `examples/DecomposingTerms.ipynb`; tests in `tests/test_terms.py`.
- `examples/circuits/cultivation/d5_cultivation_gidney_s.stim`: Gidney, Shutty and Jones's own d = 5 cultivation circuit with `S` for `T` (their Zenodo data, doi:10.5281/zenodo.13777072, CC BY 4.0; `for_perfectionist_decoding/...d1=5.stim`, unchanged below a header). It has the same CNOTs, resets, measurements and noise, in the same order, as SOFT's `d5_cultivation.stim` with `d5_final_check.stim`; it tracks the growth's Pauli corrections in its detectors instead of applying them, uses another pattern of `S` and `S_DAG` in the d = 5 double-check, and measures its final check in one `MPP`. On it, as published, Stim's search and `codedistance`'s exact `MIPDist` both give fault distance 4 (graph-like search: 5), as on SOFT's circuit: 4 is the fault distance d = 5 cultivation is designed to have before its escape stage (Chan et al., arXiv:2609.17706, Sec. 2.3: 5 with four rounds of checks instead of three). `examples/CircuitDistance.ipynb` compares the two files and computes it; the earlier text there and in the paper that called it "4, not 5" is corrected. Test in `tests/test_distance.py`.
- `zxqec.qprogram.z_distance_through_t`: the Z circuit distance of stages whose only non-Clifford gates are `T` and `T^dag`, after checking that replacing them by identities is exact. A Z fault commutes with `T`, so it flips the same results with and without the gates; the Z distance is that of the stages without them (`without_gates`, then `circuit_distance(kind='Z')` against the code the real stages end in) provided that (1) the two have the same detectors, checked on the noiseless circuits with and without the `T` gates between the same boundary checks (the derived detectors, the final logical measurement left out, span the same space), and (2) no Z fault can trigger a fed-forward X correction, which would be an X error in front of later `T` gates, checked by requiring every X correction to be controlled by Z-basis results. Otherwise `TRemovalError` says which failed. Any other non-Clifford gate raises `NotCliffordError`; stages that are not phase-free without their `T` gates raise `NotPhaseFreeError`. Both cultivation circuits pass, with Z distance 3 (d = 3) and 4 (d = 5) as before; two small programs that fail each check (`T T` on a helper in |+> before its X measurement; an X correction from an X-basis result followed by a `T`) are refused. `_annotated` was split into `_detector_rows` and `_split_off` (no change in what `circuit_distance` computes). `examples/CircuitDistance.ipynb` uses it; tests in `tests/test_distance.py`.
- The fold-transversal Hadamard with another CNOT order: `examples/circuits/ft_h/ft_h_3.2_n_order.qasm` and `ft_h_5_n_order.qasm` run the weight-4 checks of the X checks of code 2 and of the Z checks after the rotation in N order (top-left, bottom-left, top-right, bottom-right data qubit) instead of the thesis's order (top-left, top-right, bottom-left, bottom-right), and `build_program(cnot_order='N')` (`--n-order`) in `examples/interactive_fold_h_3d.py` uses them; the default is unchanged. In the thesis's order a fault on a check's helper half way through spreads onto a horizontal pair of data qubits, along code 2's logical X (stage 3) and code 1's logical Z after the rotation (stage 5), so stages 1-6 have circuit distance 2; in N order the pair is vertical, each change raises the distance of its own round (stages 1-3, 5-6) from 2 to 3, and with both stages 1-6 have circuit distance 3, the distance of the codes. All checks of a stage have the same type, so the noiseless program is the same (`compare_programs`: logically equivalent). `examples/CircuitDistance.ipynb` shows it; test in `tests/test_distance.py`.
- `zxqec.qprogram.circuit_distance`: the circuit distance of Clifford stages of a program, the smallest number of faults under circuit-level noise that changes the logical information without a detector noticing, found by Mark Webster's `codedistance` library (`circuitDistance`, by default with the exact integer program `MIPDist`; its Chromobius filter is switched off). The stages are written as a Stim circuit between noiseless `MPP` checks of the codes before and after them (stabilizers and one logical operator); the detectors and the observable are derived by zxqec from the noiseless circuit, so nothing is written by hand and a logical gate in the stages (such as a logical Hadamard) needs no special case; Stim checks that they are deterministic. `kind='full'` (depolarizing noise after every gate, flips after resets and before measurements), `'Z'` or `'X'` (Z or X faults only), or a sequence of these. A `T` gate or a correction other than a fed-forward Pauli raises `NotCliffordError`; the Z and X distances of stages that are not phase-free (a Hadamard that is not part of an X-basis reset or measurement, or an S) raise `NotPhaseFreeError`. One logical qubit after the stages for now. `without_gates(program)` removes the `T`-type gates: since Z faults commute with them, the Z distance of a phase-free circuit with single-qubit `T` gates is that of the circuit without them, measured against the logical of the code the real circuit ends in (`code_out`), when the two have the same detectors and no Z fault can trigger an X correction (`z_distance_through_t` checks both); the X distance found that way is not the real one. Results: the fold-transversal Hadamard's rounds (stages 1-6, from the encoded [[9,1,3]] code to the encoded code) have circuit distance 2, from hook errors (two faults on check ancillas half way through their CNOTs), and the mis-wired ones 1; d = 3 cultivation (Wan et al.) has Z distance 3; the d = 5 circuit from SOFT has Z distance 4. Checked independently with Stim alone on the published SOFT files with their own noise, detectors and observable, with T replaced by S as in Gidney et al.'s simulations: fault distance 3 at d = 3 and 4 at d = 5 (Stim's graph-like search reports 5 there; the lightest error is not graph-like), the values `circuit_distance` gives for the same circuits. `CircuitDistance.explain()` returns a lightest undetectable fault set, found by Stim's own search in the same circuit, as `Fault(stage, operation, pauli)` (each stage starts with a `TICK`, so the stage is exact): for the fold-transversal Hadamard, `X15 Y5` and `Y16 Y5` right after `CX 15 5` and `CX 16 5` in stage 3, which leave the logical `X6 X7 X8` and change no result; for the mis-wired one, a single fault on helper 10 in stage 6, whose check the mis-wired Z check makes random; for d = 5 cultivation, one Z fault in each of stages 3, 4, 5 and 7. When the stages start after stage 0, the input boundary also measures the Pauli of every fixed qubit at the cut (`fixed_qubits()`), so a helper that the program prepared in |+> and uses later is in |+> (before, it started in |0> and the checks it does measured nothing: the fold-transversal rounds had 24 detectors instead of 29; the distance, 2, is unchanged). `examples/CircuitDistance.ipynb` walks through all of this. Optional dependencies: `pip install zxqec[distance]` (stim, codedistance). Tests in `tests/test_distance.py`, skipped without them.
- Fixed: the classes of runs of a block. `logical_action(..., context=...)` takes detectors of the program around the block; those that mention none of the block's own outcomes restrict its classes of runs to what the program can produce, so an outcome measured before the block that the program fixes (it can appear in a sign of the code before the block) is read as its value. Detectors that mention the block's own outcomes are left out, so a check whose outcome the program predicts is still analysed as a measurement. `summary()` and `QProgram.logical_action(level, index)` pass the whole program's detectors. A parity written in another order, or plus 1, is no longer counted as a second parity. ### Changed
- `LogicalAction.branches()` follows the paper's decompilation flow (`route='flow'`, the default): a class of runs whose map is Clifford is named from the stabilizers of its Choi state (`zxqec.codes.flow`), with no matrix; only a non-Clifford class (or the zero map, or a scalar) is named by its matrix, as before. The four questions the matrix route asks (the name and Pauli correction, the split into code blocks, the Pauli that relates a class to the first, whether it is unitary) get the same answers: same order of trying Paulis and names, checked on every block the test suite names and on all example notebooks. `route='matrix'` keeps the old way. New `LogicalAction.path()` (which branch of the flow a gate takes) and `LogicalAction.normal_form()` (the isometry AP normal form of a Clifford isometry, or the reduced AP form of the Choi state of a Clifford map that is not one, such as a block that measures); `named_by` counts the classes named each way.
- `code_of`: for a layer of Clifford phase gadgets (every angle a multiple of pi/2) the stabilizers that survive the gadgets are found by Gaussian elimination, as the kernel of one matrix, instead of by listing the 2^r patterns of the r independent gadget parities; there is no longer a limit of 14 such parities for Clifford diagrams. Non-Clifford layers are read as before.
